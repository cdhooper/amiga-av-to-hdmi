# Hardware Configuration

This document describes the configuration boundaries between the Amiga Pi to HDMI board and the software running on its Raspberry Pi and STM32.

## Configuration layers

There are three separate software components:

1. **RGBtoHDMI on the Raspberry Pi**
   - Captures and processes the Amiga video.
   - Processes the digital Amiga audio.
   - Generates the HDMI video signal.
   - Provides the display processing and user interface.

2. **FlashFloppy on the Gotek**
   - Emulates the Amiga floppy drive.
   - Provides the display/I2C interface used by FF OSD.

3. **FF OSD firmware on the board's STM32F103**
   - Receives FlashFloppy display information.
   - Places that information into the Amiga video display path.
   - Provides optional Amiga keyboard control of FlashFloppy.

Keep these configuration layers separate when troubleshooting.

## Raspberry Pi / RGBtoHDMI

The Raspberry Pi runs the [RGBtoHDMI](https://github.com/hoglet67/RGBtoHDMI) software.

Follow the RGBtoHDMI documentation for:

- Raspberry Pi software installation.
- SD-card preparation.
- RGBtoHDMI configuration.
- Supported video profiles.
- Display and scaling settings.
- Button configuration.

The board provides the Amiga-specific hardware interface; RGBtoHDMI remains responsible for the video processing.

## GPIO and video capture

The exact Raspberry Pi GPIO assignment is revision-specific and is documented by the board's schematic and GPIO usage documentation.

The Rev3-and-later CPLD capture architecture uses CSYNC to capture timing information. This is one reason the later boards do not require the timing adjustment used by the previous discrete logic versions (Rev1 and Rev2).

## HDMI routing

The onboard HDMI switch has two inputs:

- **Pi HDMI** -- the HDMI output generated by RGBtoHDMI.
- **Secondary HDMI** -- a second internal HDMI video source.

The switch output feeds the rear-facing HDMI connector.

Normal operation selects the Pi input. The secondary input can be selected when the board is being used as an HDMI switch as described in [Using the Board](usage.md).

## Secondary HDMI source

The secondary HDMI input is intended for an internal HDMI source.

The exact connector arrangement depends on the PCB revision:

- Rev7.2 uses a female secondary HDMI connector.
- Earlier revisions use a male secondary HDMI connector.

## Audio

Rev6 and later provide integrated HD Audio capture.

Rev7.1 contains fixes intended to improve captured audio. If you have a Rev6 or Rev7 board, ensure that R20 and R21 are 470 Ohm.

Analog audio capture to digital is performed by the PCM1808 on the Amiga AV to HDMI board. The digital data is then provided to the RGBtoHDMI software on the Pi for inclusion with the HDMI video stream.

Be sure to install the latest version of the RGBtoHDMI software.
Ensure the RGBtoHDMI HDMI is enabled:
    `Settings / HDMI Manual Mode = HDMI (Auto RGB/YUV)`
Enable RGBtoHDMI HDMI Audio
    There is a dedicated menu for configuring HDMI Audio.

## FlashFloppy

The board's STM32 communicates with a FlashFloppy Gotek using the FlashFloppy display interface.

For general FlashFloppy setup, see:

- [FlashFloppy Initial Setup](https://github.com/keirf/flashfloppy/wiki/Initial-Setup)
- [FlashFloppy OSD Hardware Connections](https://github.com/keirf/flashfloppy-osd/wiki/Hardware-Connections)

FlashFloppy configuration files such as `FF.CFG` control FlashFloppy itself. They are not configuration files for RGBtoHDMI.

The FlashFloppy documentation notes that `FF.CFG` controls drive emulation and display handling, and that configuration files can be placed in the `FF/` directory or at the root of the USB drive. If an `FF/` directory exists, the root is not searched for those files.

## Recommended FlashFloppy configuration

Use a current [FlashFloppy](https://github.com/cdhooper/flashfloppy-osd-avhdmi/releases) release.

The FF OSD interface is separate from the floppy-bus configuration. Consult FlashFloppy documentation for more information.

## CH340 serial interface

Rev7 and later include a CH340 USB-to-serial interface for the STM32.

This is useful for development, programming, and diagnostics of the FlashFloppy OSD.

If the USB serial device is not detected, troubleshoot the CH340 hardware separately from the STM32 firmware.
